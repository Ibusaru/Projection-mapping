# ビーチ・海面・ドローンカメラ 実装方針

## 目的

SampleScene の最初の数十秒で、次の体験を成立させる。

1. ビーチリゾートを主役にした、自然なドローン空撮から始まる。
2. 波打ち際、パラソル、サンベッド、ヤシが同じ画角に入り、「ビーチがある」と一目で分かる。
3. ドローンが海へ近づく動きの延長で水中へ入り、別シーンへの切替には見えない。

この文書の画づくりと合格条件を、従来のカメラ数値条件より優先する。

## 現状の失敗と原因

### 1. 最初の画角

現状は高さ約 100 m、俯角約 42 度、FOV 約 56 という数値だけを満たしている。しかし注視点がビーチ施設ではなく、広い砂メッシュの中央へ寄っている。そのため、画面の大半が模様のない砂になり、海岸線が下端で切れ、マップ端のように見える。

数値上の「空撮」を合格扱いにせず、画面内の構成要素と占有率を検証する必要がある。

### 2. ビーチ装飾

装飾は生成処理を通っていても、空撮の注視領域と配置領域が一致していない。また、配置失敗時にスキップする実装のため、最終的な生成数が保証されない。結果として、画面上は装飾のない砂浜になる。

今回の直接原因は、Asset Store のモデル名から解決していた参照が、実体メッシュを持たないラッパー／空のPrefabだったことだった。従来ログでは `Instantiate returned null` が連続し、試行回数だけ増えて `children=0` になっていたため、配置ロジック以前に表示対象が生成されていなかった。現在は `Assets/Simple_Beach_Models/Models/*.fbx` の実体ルートを優先して解決し、万一アセットが欠けても簡易プロシージャル小物へフォールバックする。

「ランダム散布」ではなく、空撮で必ず見える固定ショーケース区画を先に完成させる。

### 3. 上空から海中への遷移

黒フェード中にカメラを海中へ移動する方式は、技術的には安全でも、体験としてはシーン切替に見える。今回の要求には合わないため廃止する。

## 目標画面

### ドローン開始画角

- 画面の 35〜55% を海面、25〜45% を砂浜にする。
- 波打ち際を画面の対角方向に通し、上下端と平行な境界にしない。
- ビーチ施設群を中央 60% の範囲へ置く。
- 地形メッシュの外周、直線的な端、空の隙間を映さない。
- カメラ高度は 65〜90 m を基準とし、画面構成を優先して調整する。
- 俯角は 35〜50 度、FOV は 48〜54 を基準とする。

### ビーチ施設群

最初に一つの固定ショーケース区画を作り、その後に背景装飾を追加する。

- パラソル: 4〜6 基
- サンベッド: 8〜12 台（各パラソルに 2 台）
- サイドテーブル: 2〜4 台
- ヤシ: 5〜8 本
- 小物: 8〜16 個

すべて乾いた砂の上へ置く。Renderer.bounds の最下部を砂面へ合わせ、水面以下、浮遊、埋没を禁止する。必要数を置けない場合は処理を成功扱いにせず、固定フォールバック座標を使用する。

## 実装構造

### 1. BeachShowcaseLayout

ビーチ施設の論理配置を一か所にまとめる。

- ショーケース中心
- 波打ち際方向、岸方向、海方向
- 各パラソルクラスタの固定スロット
- ヤシの固定スロット
- 空撮用 Bounds
- カメラ用の注視点

地形、装飾、カメラが同じレイアウトを参照する。乱数はスロット内の微小な回転・間隔だけに使い、存在数や大まかな場所を乱数に任せない。

### 2. BeachShowcaseBuilder

生成を次の順序に固定する。

1. 乾いた砂面を評価する。
2. パラソルクラスタを必須数生成する。
3. サンベッドとテーブルをクラスタ相対座標で生成する。
4. ヤシを外周へ配置する。
5. 接地・乾燥・重なりを検証する。
6. 不合格スロットだけフォールバック位置で再配置する。

背景へのランダム散布は、この必須区画が完成した後だけ行う。

### 3. DroneCameraRoute

カメラ経路はマップ全体ではなく `BeachShowcaseLayout` の Bounds から作る。

#### Phase A: Establish（4〜6 秒）

- ビーチ施設群と海面を斜め上空から見せる。
- 横移動は緩やかにし、開始直後から主役が画面中央にいる状態にする。

#### Phase B: Approach（5〜8 秒）

- 波打ち際に沿って前進しながら高度を下げる。
- パラソル群を横切り、海面を画面中央へ増やす。
- 急旋回、急降下、注視点の飛びを禁止する。

#### Phase C: Water Entry（0.6〜1.0 秒）

- カメラの進行方向を維持したまま、水面を画面全体へ近づける。
- 水面通過の前後で位置と向きを連続させる。
- 0.2〜0.35 秒だけ屈折、色収差、露出低下、泡の薄いオーバーレイを使う。
- 黒画面、完全フェード、瞬間テレポートは禁止する。

#### Phase D: Underwater Continue

- 入水直前と同じ進行方向で水中移動を継続する。
- 1〜2 秒かけて通常の水中カメラへブレンドする。
- 魚へのフォーカスはこのブレンド完了後に始める。

## 海面

- 海面は一枚の連続メッシュにする。
- シーンの生成領域は `420 x 280`、魚の主活動領域は `100 x 68` に固定し、陸地を広げず海を主役にする。
- カメラ開始FOVは `52` 度。海面バックドロップのZ方向だけを延長し、有限地形の外周が空撮フレームへ入らないようにする。
- 外周がカメラに入らない大きさを保証する。
- 上空では海底が全面的に透けないよう、視線角に応じて不透明度を上げる。
- 岸付近だけ浅瀬色を使い、沖は深い青緑にする。
- 波は頂点を大きく変形せず、法線の二方向スクロールを基本にする。
- 長い直線状の泡、光線、スパークルは作らない。

## 実装順序

### Step 1: 静止画を先に完成

- 自動ツアーを一時停止する。
- 固定カメラで開始画角を作る。
- 必須ビーチ施設を固定スロットへ配置する。
- 1280x720 の PNG を保存し、この段階で画角と配置を確認する。

### Step 2: ドローン移動

- Establish と Approach だけを実装する。
- 位置、回転、FOV の速度上限を設ける。
- 開始、中間、入水直前の 3 枚を保存して比較する。

### Step 3: 入水遷移

- 黒フェードを削除する。
- 水面通過の位置・向き連続性を実装する。
- 入水直前、入水中、水中直後を保存する。

### Step 4: Validator

画面に見えない数値検証だけで完了にしない。次を検証する。

- 必須装飾数
- 全装飾の乾いた砂への接地
- 開始画角でショーケース中心と海面注視点が viewport 内
- 開始画角で海面と砂浜の両方が viewport 内
- 地形外周がカメラの far/side frustum に入らない
- カメラ位置・回転が入水前後で連続する
- 黒フェードの最大アルファが 0.35 以下
- 水中装飾にパラソル・ヤシ・サンベッドが存在しない

## 合格条件

以下をすべて満たすまで完了扱いにしない。

1. 開始画像だけで、海、波打ち際、パラソル、サンベッド、ヤシを確認できる。
2. 画面端に地形メッシュの直線的な外周や空の欠けがない。
3. パラソル 4 基、ヤシ 4 本、サンベッド 8 台、テーブル 2 台以上が開始画角または開始後 3 秒以内に見える。
4. 装飾が水中、浮遊、埋没していない。
5. 上空から入水まで黒画面を挟まず、同じ移動の連続に見える。
6. 入水前後でカメラ forward の角度差が 12 度以下、画面上の移動対象が維持される。
7. Unity Console のコンパイルエラーが 0 件。
8. Validator が成功し、開始・中間・入水直前・入水中・水中直後の画像を目視確認済みである。

## 今回破棄する方針

- 高さ、俯角、FOV の数値だけで空撮を合格にする。
- マップ全体の Bounds をカメラ構図に使う。
- ビーチ装飾の存在数をランダム配置の成功に任せる。
- 黒フェード中にカメラを海中へテレポートする。
- Validator が通っただけで見た目を確認せず完了にする。
